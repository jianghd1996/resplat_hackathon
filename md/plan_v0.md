# A/B 插件实验计划 v0

目标：保持官方 ReSplat 代码、权重及前向过程不变，只迭代模块 A（输入视角与预处理）和模块 B（从 ReSplat PLY 接续优化）。所有策略跨场景使用同一套参数，按 `md/main_table.md` 记录质量和时间。赛题要求 B 耗时严格小于本机经典 3DGS 的 `30000 × T_iter`；同时优先争取接近 10% 时间预算的满分区间。PSNR/SSIM/LPIPS 权重分别为 20/20/40，时间为 20。

当前入口：`baseline/run_pipeline.py --scene ... --output ... --module-a uniform16 --module-b fastgs`。A 策略放在 `baseline/utils_A/<名称>.py`，暴露 `select(train_indices, count)`；B 适配器放在 `baseline/utils_B/<名称>.py`，接受 `train`/`render` 动作。`uniform16` 与 `fastgs` 对应现有 baseline，输出实验目录 `results/baseline_A_baseline_B/`。新增策略时需要登记 CLI 选择、统一的输出目录命名和评测渲染器，且在相同输入、相同测试拆分下做消融。

| 优先级 | 待测模块 / 文件建议 | 实验与判据 |
|---|---|---|
| P0 | 桥接与计时回归（现有 `run_resplat.py`、`summarize.py`） | 核对 PLY 坐标/四元数/SH/opacity 约定，实测同分辨率、同视角数的经典 3DGS `T_iter`；按 A、ReSplat、B 分段记录时间与测试集指标。 |
| P1 | A：`utils_A/fps.py` | 在训练候选相机中心上做确定性最远点选取；与 `uniform16` 对比覆盖度、ReSplat 输出和最终测试指标。候选池与 B 的训练监督池保持不变。 |
| P1 | B：`utils_B/short_budget.py`、`short_schedule.py`、`no_reset.py` | 分别测试统一迭代预算、短程位置学习率日程与禁用 opacity 重置；已完成的门槛及结果见下方。 |
| P1 | B：`utils_B/topk_growth.py` | 独立测试硬点数预算下的 top-k 密集化；与 `no_reset7000` 单项对照。 |
| P1 | B：`utils_B/coarse_to_fine.py` | 独立测试前 40% 半分辨率、后 60% 全分辨率的训练日程；与 `no_reset7000` 单项对照。 |
| P2 | A：`utils_A/coverage_local.py`、`utils_A/quality_filter.py` | 测边界覆盖加邻近共视、统一阈值模糊帧过滤；不能按场景手工选帧或调阈值。 |
| P2 | B：`utils_B/regularized.py` | 在已验证的短程训练器上试重要性剪枝、视图锥尺度约束、曝光补偿，重点观察留出集 LPIPS；曝光若用于训练，评测渲染也必须保持一致。 |

测试顺序：先锁定同一批三组主场景和统一训练/测试划分，再逐个替换 A 或 B，之后测试 A/B 组合。每次记录 Git 提交、环境、权重校验和、参数、位姿来源、图像数/分辨率、阶段计时、PSNR/SSIM/LPIPS、标准 PLY 和渲染 PNG。大文件与原始 JSON 留在服务器端 `results/`；将可核实的汇总写入 `md/main_table.md`。上表是初始模块队列；已完成和待测状态以下方清单为准。

## 外部启发候选与本项目处置（2026-10-30）

- [x] P1 / `utils_A/pose_coverage.py` 本轮不做：FPS 在 `counter` 上降低固定点集的视锥
  覆盖率，说明相机中心距离遗漏方向与可见性。以训练相机中心和前向方向构造
  跨场景归一化的姿态距离，贪心选 16 张；统一权重，不使用测试相机或测试图像。
  预计只增加相机数量乘以 16 的几何计算。对照 `uniform16` 与 `fps`，失败判据
  沿用三场景 LPIPS/PSNR，并核对同一点集视锥覆盖率。实测 `coverage_local`
  已加入前向方向，三场景 LPIPS 全部变差；`counter` 上将锚帧数从 8 扫到
  16，固定点集覆盖率最高 96.47%，仍低于均匀基线 99.14%。因此停止
  仅依赖相机中心和方向的另一种贪心近似。真正使用场景可见性/遮挡的新方案
  仍可在后续版本单独立项，不能把本次失败推广到该类方法。原候选受
  [Chen 等，CVPR 2026，Coverage Optimization for Camera View Selection](https://openaccess.thecvf.com/content/CVPR2026/html/Chen_Coverage_Optimization_for_Camera_View_Selection_CVPR_2026_paper.html)
  启发的低成本近似；论文的方法依赖场景覆盖信息，我们的姿态代理并非其实现。
- [x] P2 / 频域质量离线审计完成，独立 A 流水线本轮不做：用统一的归一化频域得分衡量候选帧
  细节，再与覆盖度共同选帧；需排查噪声、运动模糊和高频纹理导致的误选。
  已在三组固定拆分上计算每张训练图 256×256 灰度 FFT 的高频能量比例，
  以同场景中位数的 0.8 倍审计原均匀 16 帧：DL3DV 5 张、HW 0 张、
  `counter` 3 张低于阈值，其中 DL3DV 5 张与 Laplacian 筛选完全相同，
  `counter` 2/3 张相同。原始统计见本机
  `results/frequency_quality_audit/audit.json`。频率指标仍可能把低纹理误当
  模糊；`quality_filter` 完整三场景评估只有一组 LPIPS 小幅改善，因此
  当前频域阈值没有独立于 Laplacian 方差的有效机制或稳定收益证据。
  来源：[Li 等，2024，Frequency-based View Selection in Gaussian Splatting Reconstruction](https://arxiv.org/abs/2409.16470)。
- [x] P2 / 短程 B 调度已完成：在有效的 5000/7000 步预算上，分别测试缩短位置学习率
  日程与跳过非末步 opacity 重置；一次只变一个参数，记录高斯数量、LPIPS 和
  B 时间。`short_schedule` 与 `no_reset` 已分别单独消融，后者是当前最佳
  质量候选；默认末步重置导致的 3000 步崩溃是本项目已观察到的实现问题。
  [Hahlbohm 等，CVPR 2026，Faster-GS](https://openaccess.thecvf.com/content/CVPR2026/html/Hahlbohm_Faster-GS_Analyzing_and_Improving_Gaussian_Splatting_Optimization_CVPR_2026_paper.html)
  可作为后续优化策略的外部参考，论文性能不作为本项目预期值。
- [x] P3 / 信息量选帧本轮不做：轻量覆盖代理无效后，可在后续版本评估
  [FisherRF，ECCV 2024](https://www.ecva.net/papers/eccv_2024/papers_ECCV/papers/02130.pdf)
  的 Fisher 信息思想；需要额外模型/导数，先量化 A 时间成本及与固定 ReSplat
  黑盒的兼容性。当前 A 原均匀选择不增加计算成本，而 B 已提供跨场景收益；
  本轮没有足够证据证明额外模型/导数的 A 开销值得投入。

## 下一轮独立 B 实验（本机即最终运行机器）

每项从同一 `uniform16 + no_reset7000` 控制组出发；固定三场景、拆分、
权重和评估器，一次只改变一项。先用 `counter` 探针：LPIPS 不改善且
PSNR 不改善，或相对原 10000 步基线的 PSNR 下降 ≥0.5 dB、LPIPS
增加 ≥0.01，即停止扩展。通过探针后跑三场景，再按同一门槛和
`B < 30000 × T_iter` 决定是否保留。结果写入 `md/main_table.md`，
不因单场景偶然收益做逐场景配置。以下各项是独立 B 插件，均不归入
`utils_B/short_budget.py`；其中单项实现前必须确认渲染与 PLY 口径。

- [ ] P1 / `utils_B/topk_growth.py`：预算制 top-k 生长。保持 7000 步、
  无 opacity 重置和短学习率日程；在每次 FastGS 密集化时，以已有
  多视图重要性门槛与累计位置梯度排序，只允许剩余点数预算内的
  top-k 候选克隆或分裂。硬上限固定为该场景输入 PLY 的高斯数，
  属于统一相对预算，不使用留出视角调参。记录每次增长候选数、
  实际增长数、峰值高斯数及 B 时间；若 B 时间不降且质量不升，停止。
- [ ] P1 / `utils_B/coarse_to_fine.py`：粗到细分辨率。保持其余 B 参数，
  前 40% 迭代用 1/2 宽高的训练相机，之后用全分辨率；FoV 和投影
  由相机加载器按尺度一致生成，测试渲染始终全分辨率。记录切换点、
  两阶段耗时与梯度阈值口径；若测试 PLY/PNG 不一致或质量门槛失败，
  停止扩展。
- [ ] P2 / `utils_B/pose_refine.py`：位姿精化。先用一张训练相机检查
  FastGS 光栅器对视图矩阵的反向梯度；若不支持，则记录阻碍并停止。
  若支持，只对训练视角学习小幅 SE(3) 残差并加统一正则，测试相机
  保持原位姿，导出 PLY 保持原世界系；先检查与 ReSplat PLY 对齐和
  `counter` 留出集，再决定是否扩展三场景。
- [ ] P2 / `utils_B/long_axis_split.py`：仅修改分裂候选的尺度长轴判据，
  预算和其他训练参数固定；先测峰值高斯数、B 时间及 `counter` LPIPS。
- [ ] P2 / `utils_B/sparse_optimizer.py`：单独替换高斯优化器，先检查
  FastGS 密集化后的参数与优化器状态兼容性；若不支持则停止。
- [ ] P3 / `utils_B/perceptual_loss.py`：单独增加统一权重的感知损失，
  将损失计算时间计入 B，先确认训练视图与留出视图没有信息泄漏；
  若 `counter` 的 LPIPS 不能补偿计算成本，则停止。

## 当前最佳配置与质量—速度取舍

下面只比较已完成三场景评估、且在每个场景均满足 PSNR 相对原基线下降
<0.5 dB、LPIPS 增幅 <0.01 的统一配置。配置名中的 A 均为
`uniform16`。表中指标与秒数是 DL3DV、`billboard`、`counter` **三场景
等权算术平均**；相对改善百分比先在每个场景以本机 10000 步基线为分母
计算，再对三个百分比等权平均。“最大 B/30k”是三场景中最大的
`B_seconds / (30000 × T_iter)`。总耗时按原始 A/ReSplat/B 阶段秒数
相加后取均值，避免 `summary.json` 中一位小数的总耗时舍入误差。
这只是可复算的对照表；仓库未给出
PSNR/SSIM/LPIPS 到官方分数的完整映射，故不把这些平均数称为官方得分。

| 统一配置 | PSNR↑ | SSIM↑ | LPIPS↓ | B 均值(s)↓ | 总耗时均值(s)↓ | LPIPS 相对改善↑ | B 相对缩短↑ | 最大 B/30k↓ | 定位 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---|
| 原基线 `fastgs10000` | 27.723 | 0.8790 | 0.1729 | 75.11 | 153.60 | 0% | 0% | 11.40% | 参照 |
| `short_schedule7000` | 27.715 | 0.8808 | 0.1698 | 59.07 | 136.46 | 2.08% | 21.35% | 9.00% | 调度对照 |
| `short_schedule5000` | 27.731 | 0.8788 | 0.1708 | 47.25 | 125.75 | 1.68% | 37.10% | 7.48% | B 均时略短 |
| **`no_reset7000`** | **27.940** | **0.8837** | **0.1631** | 60.22 | 137.42 | **6.05%** | 19.97% | 9.78% | **质量与本机 10% 时间档优先** |
| **`no_reset5000`** | 27.729 | 0.8801 | 0.1674 | 47.76 | **125.24** | 3.65% | 36.50% | 7.69% | **端到端速度优先** |

- **质量与本机时间档优先：**`--module-a uniform16 --module-b no_reset`
  配合 `ITERATIONS=7000`。它在三场景的平均 PSNR、SSIM、LPIPS 均优于
  上表其他通过门槛的配置；三场景 LPIPS 相对原基线分别降低
  11.40%/4.13%/2.61%，B 时间分别为 57.67/54.86/68.14 秒。
  其中 `counter` 的 9.78% 距 10% 时间档很近，远端需重新计时。
- **端到端速度优先：**同一 A/B 配合 `ITERATIONS=5000`。
  三场景总耗时均值 125.24 秒，比 7000 步少 12.18 秒；B 均值
  少 12.47 秒，但三场景的 PSNR/SSIM/LPIPS 均略差。它仍通过
  质量门槛，且最大 B/30k 为 7.69%，提供更大的时间余量。
  `short_schedule5000` 的 B 均值仅快 0.51 秒，LPIPS 均值较差；
  单次计时不支持把这 0.51 秒解释为稳定的速度优势。

原始三场景逐项指标、A/ReSplat/B 同次运行计时、PLY/PNG 证据见
`md/main_table.md` 与本机 `results/<A>_A_<B>_B/`。历史 RTX 4090
记录、首次 HW 建图时间和本机复用位姿后的计时没有混入此表。
部分扩展实验在不同 GPU 上并行运行，耗时排序仍需远端复验。

## 已测模块的效果归纳

下表的百分比是三场景**各自相对指定对照组的百分比变化再取等权平均**。
“稳定”仅表示本轮三个场景变化同向；目前每个配置每场景仅有一次完整
运行，不代表跨随机种子的统计显著性。PSNR 保留 dB 差值，避免把
dB 直接解释为百分比。

| 单模块变化及对照 | 留出集质量效果 | 速度效果 | v0 结论 |
|---|---|---|---|
| A `fps` ← `uniform16`，B 固定 10000 步 | LPIPS 两景仅改善 0.0002/0.0007，`counter` 恶化 0.0085；三景平均相对恶化 1.18% | B 均值多 2.14s；A 时间没有稳定增减 | 淘汰，`counter` 固定点集视锥覆盖率下降 |
| A `coverage_local` ← `uniform16`，B 固定 10000 步 | LPIPS 三景均恶化，平均相对恶化 4.00%；DL3DV PSNR -0.697 dB | 总耗时均值多 3.33s | 淘汰；姿态邻帧过度集中 |
| A `quality_filter` ← `uniform16`，B 固定 10000 步 | LPIPS 一景改善、两景恶化，平均变化约 0%；没有稳定质量增益 | A 均值多 2.63s；总耗时均值多 8.97s | 淘汰；低纹理与模糊可能混淆 |
| B 默认日程 7000 步 ← 原 10000 步 | LPIPS 三景均恶化，平均相对恶化 6.44%；DL3DV/`counter` PSNR 跌破门槛 | B 平均相对缩短 20.55% | 单纯截短不可用 |
| B 缩短位置学习率日程 ← 默认日程，同为 7000 步 | LPIPS 三景均改善，平均相对降低 8.00%；PSNR 两景提高、一景 -0.023 dB | B 均值少 0.71s，场景间有波动 | 保留短日程，不把单次时间差归因于日程 |
| B 跳过中途 opacity 重置 ← 短日程，同为 7000 步 | LPIPS 三景均改善，平均相对降低 4.08%；PSNR 三景均提高 | B 均值多 1.15s，其中 `counter` 多 5.40s；该场景仍占本机 30k 的 9.78% | 当前最强的单 B 改动 |
| B 跳过中途 opacity 重置 ← 短日程，同为 5000 步 | LPIPS 三景均改善，平均相对降低 2.00%；SSIM 三景均提高，DL3DV PSNR -0.134 dB | B 均值多 0.50s，场景间有波动 | 速度优先的可行方案 |
| B 最终多视图剪枝 ← 短日程，同为 7000 步 | **仅 `counter` 门槛探针**：PSNR -0.204 dB，LPIPS +0.0001 | `counter` B 多 1.58s | 门槛未过，未测另两景 |

因此当前只保留 `uniform16` A 与无重置短日程 B。已测 A 模块没有
稳定收益，按单项先验不安排 A/B 组合；跳过的候选均在上方注明了
“未实测”的边界与重新立项条件。
